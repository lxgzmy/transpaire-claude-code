# Scripts — Permit Officer

Stdlib-only Python (no third-party packages on the server), mirroring the
contract-admin scripts convention — except `osc_snapshot.py`, which borrows
the OSC MCP server's virtual environment for its HTTP client. The three
`.ps1` scripts are PowerShell 7 and belong to the scheduled run. All read-only
against business files and OSC; outputs go to `runtime\permit-officer\` only.

| Script | Purpose |
|---|---|
| `xlsx_min.py` | Minimal stdlib `.xlsx` reader + multi-sheet writer (no openpyxl on the server). Reading never modifies a workbook. |
| `osc_snapshot.py` | Snapshot step: one JSON per pilot job (job, activities, alerts, documents) from the **production** OnSite Companion, GET only, through the `osc_mcp` client the MCP server uses. Runs under `shared\mcp\osc-api\.venv\Scripts\python.exe` (needs `httpx`); refuses a stale copy; retries a passing network fault twice; reads the jobs side by side; writes only under `runtime\`. |
| `ba_report_parse.py` | Weekly BA report → row model. Columns are located **by header text** (the export gained five columns on 28 Sep 2026); unknown columns are carried verbatim; "Submit all RFI Items" is required. Reads the "PENDING …" / "RESOLVED …" item list, the v0.3 **Items** sheet (per-item values, one row per item, matched by Job No. + Item) and, for older drafts, the v0.2 L–O columns. `officer_edits()` compares a draft as the officer left it with the draft as written. |
| `ba_report_draft.py` | Deterministic Monday draft (v0.4): last week's report + per-job OSC snapshot JSONs → draft workbook (main sheet = the base's columns exactly; Items sheet = one row per item) + evidence bundle. Per item: Assigned to, Date submitted, Date resolved, Days outstanding in NSW business days, YELLOW/RED by tier (`TIERS`, `ASSIGNEE_TIER`, PO-11a) or the item's own limit (PO-11b; engineering by stage, `ENGINEERING_STAGES`, PO-11c); engineering and covenant also tracked from their columns (`COLUMN_CYCLES`). Items resolve only on fresh evidence or the officer's Date resolved and show once as RESOLVED; everything uncertain is kept and flagged. `--edited` reads her Items-sheet changes from last week's draft; `--jobs` scopes the pilot. |
| `ba_weekly_run.py` | The Monday run in one command: finds her latest export in the archive (never an older one), copies her edited draft from the drop folder, snapshots OSC, drafts, delivers to the drop folder without overwriting a draft she may be editing, keeps the delivered copy and reads it back. A self-check (the regression suite, beside the snapshot, skipped for code that already passed) comes first; her Save As copy is found; an open or untouched draft is said; a restart is done once. Last week's draft is scored against her report for the same week (`compare-dd.mm.yyyy.md`, kept on a re-run), the headline in the summary. `--dry-run`, `--restart LABEL` (week 1), `--force`, `--no-self-check`. |
| `safe_files.py` | Puts a finished file in place on the `Z:` share. A swap or copy the share refuses for a moment (`WinError 5` or `32`) is tried again for about five seconds; any other error is raised at once. |
| `register_ba_weekly_task.ps1` | Run once by a person: sets up (or replaces, or with `-Remove` takes away) the scheduled task that starts the Monday run at 06:30 and 12:30 each Monday, Tuesday and Wednesday. It asks for the account's password, which Windows keeps with the task. `-Show` says what would be registered and changes nothing. |
| `ba_weekly_task.ps1` | What the scheduled task starts: maps `Z:` for the run, then runs `ba_weekly_run.py --scheduled`. Each run's output goes to `runtime\permit-officer\logs\ba-weekly-<date>.log`. No stop is silent: when the run ends without a draft or a note in the drop folder, or without a line in `ba-weekly-runs.log`, the wrapper leaves them itself. A checkout not on `main` still runs, with a warning in both logs. |
| `ba_weekly_status.ps1` | Read-only check, any time: `OK` or `NEEDS A PERSON`, with each reason on its own line. Covers the task's registration, sign-in, last result and latest slot, this week's draft or note, the checkout's branch and, from 1 November, next year's holidays and shutdown dates. Exit code 0 or 1. |
| `nsw_holidays.py` | NSW public holidays 2026–27, the Christmas shutdown (`SHUTDOWNS`, one pair per break as the officer gives it: her last business day, the day work resumes) and `business_days()`; verify each new year before the first Monday run. |
| `compare_ba_report.py` | Pilot scorecard: AI draft vs the officer's real report for the same Monday → matched / missed / extra items per pilot job and the "% correctly pre-populated" headline (criterion 90 %), titled by the draft's week. The Monday run calls it; by hand only for another pair. |
| `regress_ba_report.py` | Regression over synthetic fixtures (fake jobs/names only). Run after any change to the scripts above; the Monday run also runs it as its self-check. Scratch files go under the checkout's git-ignored `runtime\shared\tmp\`, never the system temp folder on `C:`. |
| `test_osc_snapshot.py` | The snapshot's retries and side-by-side reads on a fake OSC client (no network). Needs `httpx`, so it runs under the osc-api environment; `regress_ba_report.py` starts it there. |

Run mechanics are in `../workflows/ba-weekly-report.md` (§How to run).
